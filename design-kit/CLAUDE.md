# 디자인 키트 규칙 (사내 클로드가 가장 먼저 읽는다)

이 키트로 HyDS3 시험 준비 사이트를 **새로** 만든다. 탭은 둘이다: **모의시험**, **시험 대비**.
화면 모양은 키트의 예시 페이지(`pages/`)를 통째로 복사해서 시작하고, 지어낸 내용 자리에 회사 자료를 넣는다.

## 꼭 지킬 것

1. 화면은 그리지 말고 **복사한다.** 새 화면은 `pages/`의 HTML 파일을 통째로 복사해 시작하고, class와 요소 구조는 그대로 둔다. 바꾸는 것은 글자, 숫자, 코드, 링크, 반복 개수뿐이다.
2. `css/design.css`, `js/design.js`, `fonts/`는 고치지 않는다. 새 CSS 파일, `style=""` 속성, 새 색·크기·간격 숫자, **글꼴 지정(font-family, 편집기의 fontFamily 설정)**을 만들지 않는다. 글꼴은 키트가 정한다. 필요한 모양이 없으면 `pages/parts.html`에서 찾고, 그래도 없으면 멈추고 사람에게 묻는다.
3. 기능 JS는 따로 `app/` 아래 파일에 둔다. 기능 JS는 class를 더하거나 빼고, aria 값과 data- 값을 바꾸는 것만으로 화면 상태를 바꾼다(아래 '상태 표시').
4. 인터넷 주소(CDN 등)를 넣지 않는다. 글꼴은 `fonts/`에 있다. 브라우저 파이썬 파일은 회사 PC에 이미 있는 것을 쓴다.
5. 한 단계가 끝나면 멈추고, 그 단계의 '확인'을 모두 해 본 뒤 사람에게 알린다. 확인에는 기준 사진(`shots/`)과 나란히 놓고 보기가 들어간다.
6. 회사 자료(시험지, 풀이, 데이터)는 회사 PC 밖으로 보내지 않는다. 깃허브 등에 올리지 않는다.
7. 짐작해서 만들지 않는다. 자료가 이상하거나 규칙과 부딪히면 멈추고 묻는다.

## 순서

`guide/00-start.md` → `01-data.md` → `02-mock-exam.md` → `03-exam-prep.md` → `04-finish.md`

## 상태 표시 (기능 JS가 바꾸는 것)

| 무엇 | 어떻게 |
|---|---|
| 지금 탭 | 머리줄 탭에 `aria-current="page"` |
| 고른 칸(세그먼트, 회차 타일, 단추) | `aria-pressed="true"` |
| 고른 목록 항목(문제 탭, 코드 후보) | `aria-selected="true"` |
| 지금 소문항(번호 칸) | `aria-current="step"`, 맞음 `data-state="done"`, 틀림 `"wrong"`, 풀어 봄 `"tried"` |
| 결과 칸 | `.k-result`에 `data-state` = `idle` · `run` · `ok` · `diff` · `error` |
| 코드 칸 | `<pre class="k-code" data-k-hl>` 색 · `data-k-lines` 줄 번호 · `data-k-lit="3-5"` 밝은 줄 · `data-k-err="4"` 오류 줄 |
| 보기(어둡게·밝게, 글자 크기), 손잡이 움직임, 메뉴 열고 닫기 | design.js가 한다. 손대지 않는다 |
| 토글(`k-seg`, `k-nav`) | 안에는 `<span class="k-thumb">` 하나와 같은 폭의 `a`·`button`만 둔다. 다른 요소를 넣거나 칸 폭을 따로 정하면 손잡이가 어긋난다(콘솔에 경고가 나온다). 손잡이 자리는 JS로 옮기지 않는다 |
| 알림 한 줄 | `kDesign.toast('복사했어요')` |

## 하면 안 되는 예

- `.k-btn { background: #3478f6 }`처럼 키트 class에 새 값을 덧쓰기
- 예시 HTML을 보고 비슷하게 새로 짜기(통째로 복사해서 글자만 바꾼다)
- 모든 화면을 한 번에 만들고 나서 한꺼번에 확인하기
