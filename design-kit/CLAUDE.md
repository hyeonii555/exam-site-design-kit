# 디자인 키트 적용 규칙 (사내 클로드가 가장 먼저 읽는다)

이 폴더(`design-kit`)는 회사 시험 준비 사이트의 **모양만** 바꾸는 키트다.
사이트의 자료, 문제, 파이썬 실행, 채점, 기록 저장은 그대로 둔다. 예외는 코드 찾기 탭 하나다(일하는 방식도 바뀐다, `guide/06-codefind.md`).

## 꼭 지킬 것

1. `css/design.css`, `js/design.js`, `fonts/`는 고치지 않는다. 사이트로 복사해서 쓰기만 한다.
2. 새 색·크기·간격 숫자를 만들지 않는다. 모양은 `pages/`의 HTML을 class까지 그대로 베낀다. 색이 꼭 필요하면 `var(--k-…)`만 쓴다.
3. 기능 코드(파이썬 실행, 채점, 자료 읽기), 자료 파일, 기록 저장 이름(localStorage 키, 파일 이름)은 바꾸지 않는다.
4. 이벤트 연결(onclick, addEventListener), id, name, 기능 코드가 찾는 class와 data- 값은 지우거나 바꾸지 않는다. 모양을 위해서는 `k-` class를 **더한다**.
5. 인터넷 주소(http, https, CDN)를 새로 넣지 않는다. 글꼴도 `fonts/`에 있다.
6. 한 번에 한 화면만 바꾼다. 화면 하나가 끝나면 그 단계의 '확인'을 모두 해 본다.
   - `python design-kit/check.py <사이트 복사본 폴더>`
   - 기준 사진(`shots/`)과 나란히 놓고 비교
   - 문제 하나를 실행해 보기
7. 원래 사이트가 아니라 **복사본**에서 일한다(`guide/00-prepare.md`).
8. 모르는 것이 있으면 짐작해서 고치지 말고, 멈추고 사람에게 묻는다.

## 순서

`guide/00`부터 `guide/07`까지 차례로 한다. 각 단계 끝의 '확인'이 모두 맞아야 다음 단계로 간다.

## 어디에 무엇이 있나

| 파일 | 내용 |
|---|---|
| `pages/index.html` | 예시 페이지 목록. 브라우저로 열어 보면서 베낀다 |
| `pages/*.html` | 화면별 예시(내용은 모두 지어낸 것) |
| `pages/parts.html` | 화면에 없는 부품: 단추, 칩, 스위치, 목록 줄, 메뉴, 확인 창, 알림 |
| `pages/codefind-demo.js` | 코드 찾기 탭의 동작 예시. 찾기 부분만 회사 검색으로 바꾼다 |
| `shots/*.jpg` | 예시 페이지의 기준 사진(맥북 14 크기 1512×945, 어둡게·밝게) |
| `check.py` | 적용 뒤 점검(파이썬 표준 라이브러리만 씀) |

## 하면 안 되는 예

- `.k-btn { background: #3478f6 }`처럼 키트의 class에 새 값을 덧쓰기
- 결과 칸을 다시 만들면서 채점 함수나 기록 저장 이름을 바꾸기
- 글꼴이나 라이브러리를 인터넷에서 불러오는 `<link>`, `<script>` 넣기
- 여러 화면을 한 번에 바꾸고 나서 한꺼번에 확인하기

## 이름 붙이는 법 (키트에서 쓰는 것)

- 부품 class는 모두 `k-`로 시작한다. 상태는 `is-on`, `is-sel`, `is-lit`, `is-ok`처럼 `is-`로 붙인다.
- 고른 것은 aria 값으로 표시한다: 탭은 `aria-current="page"`, 단추 묶음은 `aria-pressed="true"`, 목록은 `aria-selected="true"`.
  - design.js가 이 값을 보고 손잡이를 옮긴다. 사이트 코드에서는 aria 값만 바꾸면 된다.
- 코드 칸은 `<pre class="k-code" data-k-hl>코드</pre>`로 쓴다.
  - 줄 번호는 `data-k-lines`, 밝은 줄은 `data-k-lit="3-5"`, 오류 줄은 `data-k-err="4"`.
