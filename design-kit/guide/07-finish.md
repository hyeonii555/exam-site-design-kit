# 7단계 · 마무리 점검

## 할 일

1. 점검 도구를 돌린다. '문제' 줄이 하나도 없어야 한다.

   ```
   python design-kit/check.py site-design
   ```

2. 화면마다 기준 사진과 나란히 놓고 본다.
   - 어둡게 한 번, 밝게 한 번 본다.
   - 브라우저 창을 맥북 14 크기에 가깝게(1512×945) 맞춰 본다.
3. 기능을 처음부터 끝까지 한 번씩 해 본다.
   - 요약 주제 하나 열기
   - 기출 문제 셋 실행하기(맞는 답, 틀린 답, 오류 나는 코드)
   - 채점하기
   - 개념 고르기
   - 코드 찾기에 문제 붙여 넣고 전체 복사하기
4. 기록을 확인한다. 문제를 하나 풀고 → 브라우저를 껐다 켠다 → 기록이 그대로 있는지 본다.
5. 시험 볼 PC(또는 같은 크기 화면)에서 한 번 열어 본다.
6. 위가 모두 맞으면 사람에게 알린다. 원래 사이트를 바꾸는 일은 사람이 정한다.
   - 원래 `site`는 지우지 말고 이름을 바꿔 남겨 둔다(예: `site-old`).

## 막혔을 때

| 보이는 것 | 볼 곳 |
|---|---|
| 글꼴이 안 바뀐다 | `k/css`와 `k/fonts`가 같은 `k` 폴더 아래에 있는지(design.css가 `../fonts/`를 찾는다) |
| 모양이 하나도 안 바뀐다 | 맨 바깥 요소에 `k-app` class가 있는지, design.css `<link>`가 사이트 CSS보다 뒤에 있는지 |
| 일부가 원래 모양 그대로다 | 그 요소에 사이트의 옛 CSS가 id(`#이름`)로 붙어 있지 않은지. 있으면 그 옛 규칙만 지운다 |
| 화면이 너무 크거나 작다 | '보기' → 글자 크기. 그래도 이상하면 `data-k-fit`을 빼고 사람에게 알린다 |
| 손잡이가 엉뚱한 탭 아래 있다 | 지금 탭에 `aria-current="page"`(세그먼트는 `aria-pressed="true"`)가 하나만 있는지 |
| 코드 색이 안 들어간다 | `<pre>`에 `data-k-hl`이 있는지. 그래도 안 되면 그 코드를 넣은 뒤 `kDesign.paint(부모)`를 한 번 부른다 |
| check.py가 '새 색'을 알린다 | 그 줄에 새로 쓴 색 숫자가 있다. `var(--k-…)`로 바꾸거나, 키트 class를 쓴다 |
